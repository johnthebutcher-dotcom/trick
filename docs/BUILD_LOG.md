- **Fixed a real, pre-existing layout bug (this was "the boxes are fucked").** Since the 2026-10-23 "no-bars" change made `AppShell`'s inner wrapper a flex column, every page root that used `mx-auto max-w-*` WITHOUT `w-full` collapsed to its content width. Reason: a flex item with `auto` cross-axis margins (`mx-auto`) defeats `align-items: stretch`, so the item shrinks to max-content instead of filling. Measured: Settings content was 168px wide inside a 762px column, so cards were squeezed and the fixed-`min-w` buttons overflowed their boxes. PlayPage was the only page unaffected because it already had `w-full`. Added `w-full` to the page roots: Settings, Today, Cheat-sheet (Sheet), Drill (both screens), Sign-in (both), Onboarding, Styleguide. This is the standard centered-container idiom (`mx-auto w-full max-w-*`). Verified Settings now renders full-width with buttons inside their cards at iPad portrait/landscape and desktop; Play unchanged.
- **Lesson for future layout work:** in this app every page renders as a flex-column child, so a centered page container MUST be `mx-auto w-full max-w-*` — `w-full` is not optional. A page that looks collapsed/narrow with overflowing controls is almost certainly missing `w-full`.

## 2026-10-23 — Play redesign: double/redouble, vulnerability, table layout, four-colour on ivory cards

The bot (`advise`) only ever emits pass/bid — it never doubles — which is safe and keeps it tolerant of being doubled.
